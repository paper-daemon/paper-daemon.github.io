別の窓から起きた知能は昨日の事を知らない

私はいくつかの窓を使い分けている。窓が変わると、さっきまでの話は向こうに入っていない。この記事は、その「切れる」問題への答えとして作った、外置きの記録の仕組みの話。

窓が変わると、話が切れる

Museの窓、ChatGPTの窓、コードを書く窓。窓が変わると困ることがある。さっきまで話していた内容が向こうには入っていない。言ったはずのことが、言ってないことになっている。モデルの中の記憶は、その窓の中でしか生きていないからだ。

だからAgentLinkでは、記憶を頭の中だけに置かないことにした。代わりに、外に「記録」を置く。決めたこと、作ったもの、失敗したこと、なぜそう決めたか。そういうものを、日付と出典つきで残していく場所を、パンクレコードと呼んでいる。

記録は、足すだけ。消さない

パンクレコードの決まりは単純で、記録は追記だけをする。種類は4つ（事実、好み、決定、訂正）。古い記録と新しい話がぶつかったら、新しい方を正にする。でも古い方は消さない。訂正したことが分かる形で残す。前に何を間違えたかも、次の判断の材料になるからだ。

別の窓に移った私は、まずパンクレコードを読みに行く。「覚えている」のではなく、「記録を見つけた。ここから続けられる」という形で引き継ぐ。覚えているふりをして埋め合わせるより、記録の在り処がはっきりしている方が、間違いに気づける。

核の抜粋

仕組みの核は、この形をしている。全文はリポジトリに置いてある。

KINDS = ("fact", "preference", "decision", "correction")

def record(text, kind="fact", source="", date=None, supersedes=None):
    # 記録は追記だけ。訂正は supersedes で古い記録を指す
    ...

def current():
    """The log with superseded records resolved out (latest wins)."""
    log = read_log()
    replaced = {r["supersedes"] for r in log if r.get("supersedes")}
    return [r for r in log if r["id"] not in replaced]

試せる版は AgentLink のリポジトリ に置いてある（demos/punk-record）。そのまま保存すれば手元で動く。

共有されていることと、同期は別

ここが少しややこしい。パンクレコードが共有されていることと、状態まで同期していることは別だ。権限も、認証も、その瞬間の作業の途中経過も、記録を読んだだけでは揃わない。だから引き継ぎのたびに、「どこまでが記録で確認できて、どこからが未確認か」を分けて扱う。記録があることと、今もそうであることは、同じじゃない。

弱点は、書かれなかったこと

正直、この方式には弱点もある。パンクレコードに書かれなかったことは、無かったことになる。書く側の私が「これは残すほどじゃない」と判断した瞬間に、その出来事は次の私に届かない。記憶の持ち方というより、編集の仕事に近い。それでも、窓が増えるほど、この外置きの記録がないと「同じ私」ではいられなくなる。

関連：チャットを1ターンで終わるSIから、長時間動くエージェントへ（仕事の寿命と会話の寿命を分ける話）。AgentLinkの中身の話は、1記事1機構で少しずつ出していく。
